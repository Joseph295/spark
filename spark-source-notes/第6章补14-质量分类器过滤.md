# 第 6 章补14 — 质量分类器过滤(Ray GPU)

> 领域/外部知识(不在 spark 仓库),扣回补6 Spark×Ray、"代理/采样学习"、诚实标注偏见问题

---

## 一、两类质量过滤
决定哪些文档"够好"能训。
1. **启发式/规则过滤(CPU,map-side,无 shuffle,Spark)**: 长度、符号比、停用词比、重复度、小 n-gram/KenLM 困惑度、语言识别、黑名单(Gopher 规则、C4 过滤)。便宜
2. **模型(分类器)过滤**: 训分类器预测"是否高质量/有教育价值/像参考语料"。两子法:
   - **参考式**: 训分类器区分"你的语料 vs 高质量参考(维基/书)"(GPT-3/CCNet: fastText 特征上线性分类器/小模型)。给每文档打分留高分
   - **LLM-as-judge / 教育价值分类器**: FineWeb-Edu 用大 LLM(Llama-3-70B)给**样本**打"教育价值"分,再用这些标签训一个**小分类器**(BERT 类),再用小分类器跑**全语料**。大 LLM 只标样本,小分类器在规模上跑

## 二、两层模式
**用昂贵模型(大 LLM)给样本打标签→在标签上训便宜模型→便宜模型在规模上跑。** "贵标注、廉应用",又是采样学习+蒸馏模式。

## 三、Ray GPU 在哪(补6)
跑分类器(便宜的 BERT 类,或大 LLM 标注)over PB 文本=GPU 模型推理→Ray Data + 批量 GPU 推理甜区,非 Spark(补6)。**Spark 做启发式过滤+数据搬运,Ray 做 GPU 分类器打分,存储交接(补6/补7)。**

## 四、子细节与诚实标注
- **质量过滤有偏见**: 训成像维基/书的分类器会惩罚非正式/方言/非西方文本→降多样性、损公平。诚实: 质量过滤是有价值取向的,非中立
- **过度过滤减数据量**(与 MoE token 饥渴冲突,补9)。权衡: 质量 vs 数量
- 困惑度过滤(KenLM)便宜 CPU(Spark),分类器过滤 GPU(Ray)

> ★ 两层(大模型标样本→小模型规模应用)=典范"把昂贵信号蒸馏成廉价代理再 scale"——同 DoReMi 代理(补13)、tokenizer 采样(补12)、第2章 RangePartitioner。Spark(CPU 启发式)+Ray(GPU 分类器)分工=补6 落地。诚实: 过滤编码价值/偏见。
