# 第 6 章补16 — 多模态数据对齐(收尾:汇聚全部前篇机制)

> 领域/外部知识(不在 spark 仓库),是 LLM 数据处理路的 capstone,汇聚补6/7/8/10/11/13

---

## 一、多模态需要配对数据
视觉-语言/音频/视频 LLM 需 **配对数据**: 图+caption、视频+转录、音频+文本、图文交错文档。

## 二、多模态独有的数据挑战
1. **配对/对齐**: 拿到(图,文)对。源: web alt-text(噪)、caption、OCR、图文交错文档(MMC4/OBELICS)。**对齐质量(caption 真描述图吗)是核心问题**
2. **对齐过滤(CLIP-score)**: 用 CLIP 模型给图文相似度打分,留高相似对(LAION 用 CLIP 过滤)。GPU 模型推理 at scale→Ray(补6/补14 模式再现!)。低 CLIP 分=caption 不匹配图=丢
3. **跨模态去重**: 图去重(感知哈希/图 embedding + ANN,补8!)、文去重、对去重。图去重用 embedding ANN(补8)同文本语义去重。也对评测去污染(补10)多模态 benchmark
4. **格式/打包**: 图文交错序列——图经视觉编码器→图 token,与文 token 交错。打包(补11)now 须处理多模态 token 流+模态边界+逐模态注意力。"文档边界"(补11)扩展成"模态边界"
5. **存储**: 大二进制 blob(图/视频)+文+embedding 一起→正是 Lance(补7)所设计(多模态 blob+向量+标量+随机访问)。Parquet 不擅大 blob;WebDataset(tar 装图文件+caption)是经典多模态训练格式
6. **规模与成本**: 视频尤甚(巨存储、解码成本)。抽帧等

## 三、管线(全部前篇汇聚)
Spark 做关系/去重/shuffle(文去重、按 key join 图文、聚合) + Ray 做 GPU 模型打分(CLIP 过滤、图 embedding、给无 caption 图**生成** caption 的模型) + Lance/WebDataset 多模态存储。
补6 Spark×Ray + 补7 存储 + 补8 ANN 去重 + 补10 去污染 + 补11 打包 在此全部汇合。

> ★ 多模态是 capstone,演练前面每个主题: embedding ANN 去重(补8)用于图、CLIP-score 过滤=GPU 分类器(补14/补6 Ray)、Lance 存 blob+向量(补7)、带模态边界的打包(补11)、去污染(补10)、跨模态数据混合(补13)。同一套机器,从"文本文档"泛化到"多模态 item"。"物理组织匹配访问模式"主线延伸: item 现在异构(blob+向量+文),存储格式(Lance)须同时服务随机访问+向量检索+blob 取——这正是为何 Lance 这类 AI 原生格式存在。
